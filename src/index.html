01 Under the skin

The body is only a shell for the network.

Take the panels away and a second car appears: a harness running along the sills, up the pillars and through the dash, with a computer at every place something has to be sensed or moved. Each box is an ECU, drawn in the colour of the bus it lives on.

02 Detail A · the router

Every message that changes wire passes through one box.

The gateway sits under the dash, left of the console. It has a port on each of the five buses and it is the only module that does. When a message has to go from one bus to another, the gateway stores it, checks it and sends it on. The pulses that stop here are doing exactly that.

    It is also the only way in: a tester on the OBD socket can only ever talk to the gateway.

    05 The network

    Why five buses, not one.

    No single wire can carry a brake command and a radar stream at once. So the car runs a hierarchy: cheap and slow where that is enough, fast and deterministic where lives depend on it. ECUs share no memory; the only way one knows anything about another is a message on a wire.

    07 Criticality

    The more it can hurt you, the more locks it has.

    Reading is open almost everywhere. Writing is gated, and on safety and high-voltage modules it is simply not done. This rule shaped every decision in the project behind this page.

    Note 1

    The golden rule. Never write to brakes, airbag, steering or any high-voltage module. A wrong coding can silently disable a safety system, or brick an ECU that then needs a factory tool to recover. Everything that was written was written only where it was reversible and verified by reading the value back.

      09 What we actually did

      Read everything. Write almost nothing.

      The honest version: this project read a great deal, wrote very little, and hit a wall it could not climb. That wall is the most interesting part.

      What worked

      • Identifying all 40 modules over DoIP by reading F187 and F19E.
      • Reading fault memories and identification blocks freely, with no key.
      • Resetting the service interval in the cluster: a write that did succeed.

      What was blocked

      • Actuator tests and most coding writes, refused by the gateway.
      • The tail-light animation: the feature is not implemented in this firmware.
      • Any write to brakes, airbag, steering or HV, by choice rather than failure.
      Note 2

      The precondition nobody documents. A coding write to the cluster (2E 0600) was rejected until we found that the ECU only accepts it after the service-interval DIDs F198 and F199 have been written in the same extended session. No security access, no SFD token, no dwell time. Just a sequence. That one finding unlocked the whole write path.

      Note 3

      The wall. The car's tail-light animations are gated behind a body-computer adaptation channel, CAN LIN Signatur Routing, and the rear-light ECUs that would render them are LIN slaves, invisible to the diagnostic bus. The feature exists in the marketing material and in the ODX. It does not exist in this car's firmware.
